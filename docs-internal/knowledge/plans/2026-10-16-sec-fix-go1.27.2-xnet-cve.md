# Bump Go toolchain to 1.27.2, golang.org/x/net to v0.60.0, docs pip floors, and golangci-lint to v2.15.0 (CVE remediation + CI fix)

- **Date:** 2026-10-16
- **Author:** praveen
- **Related PR(s):** TBD
- **Related issue(s) / JIRA:** NO-JIRA (security remediation)

## Context

A trivy CI scan flagged two HIGH findings across all five Go binary images
(amd-metrics-exporter, amdgpuhealth, metricsclient, amd-test-runner, plus
the agfhc test-runner variant):

- `stdlib` 1.25.13 — CVE-2026-78667, CVE-2026-78669, CVE-2026-97031, fixed
  in 1.26.9 / 1.27.2. Go only maintains the latest two minor branches, and
  1.25.x had already rolled off support, so a point patch wasn't available —
  the fix is a toolchain bump.
- `golang.org/x/net` v0.58.0 — CVE-2026-78669, fixed in v0.60.0.

The docs/sphinx pip CVE track (ROCm/k8s-device-plugin#256, #257 pattern:
security floors for cryptography/gitpython/pyjwt/soupsieve/tornado/urllib3
in `docs/sphinx/requirements.in`) was already fixed on `main` in `e65f566ec`
(#1654) for the CRITICAL/HIGH findings. #256 also cleared a set of
MEDIUM/LOW findings in the same file that #1654 didn't touch — idna,
Jinja2, Pygments, PyNaCl, requests — which were still open as Dependabot
alerts on the ROCm mirror. This PR closes that remaining set too, folded
into the same change since both tracks touch unrelated files (Go toolchain
vs. docs lockfile) and ship together more easily as one PR.

The go1.27.2 bump broke the `api-checks` CI job (`make checks` = `gen vet
lint`), confirmed via `jobc target log` on the failing run: golangci-lint
v1.64.8 bundles an older `golang.org/x/tools` gcexportdata that only reads
export-data format version 2, while go1.27.2 writes version 5, so every
package typecheck failed ("could not load export data ... export data
version 5 is greater than maximum supported version 2"), cascading into
spurious `X.Lock undefined` errors for every type embedding
sync.Mutex/RWMutex. This is folded into the same PR/branch since it's a
direct, unavoidable consequence of the toolchain bump above.

## Approach

- Bump `go.mod` to `go 1.27.2` (+ explicit `toolchain go1.27.2` directive),
  picking the newer of the two maintained branches (1.26.9 / 1.27.2) since
  it also folds in several other Go 1.27.x security fixes.
- Update the builder image chain in lockstep: `tools/base-image/Dockerfile`
  (go1.27.2 download), `dev.env` (`DOCKER_BUILDER_TAG` v1.17 -> v1.18),
  `box.rb` (from-tag v1.17 -> v1.18), and the `Makefile` `mod:` target's
  `go mod edit -go=` pin.
- Update the `golang.org/x/net` replace directive in the `mod:` target from
  the stale `v0.29.0 => v0.36.0` pin to `v0.58.0 => v0.60.0`. The old pin
  was already a no-op — MVS had moved the resolved version to v0.58.0 well
  before this change, so the replace's old-version key no longer matched
  anything. Collapsed to a single replace line instead of leaving both
  pins stacked.
- Rebuilt the `${DOCKER_REGISTRY}/device-metrics-exporter-build:v1.18`
  builder image and ran `make mod` inside it to regenerate `go.sum` and
  `vendor/`.
- Added `idna==3.15`, `jinja2==3.1.6`, `pygments==2.20.0`, `pynacl==1.6.2`,
  `requests==2.33.0` to the `# Security floors` block in
  `docs/sphinx/requirements.in`, matching the lowest patched release for
  each (same selection rule as the existing floors). Regenerated
  `docs/sphinx/requirements.txt` via `pip-compile --resolver=backtracking`
  under Python 3.10 (matching `.readthedocs.yaml`); never hand-edited.
- Bumped golangci-lint `v1.64.8` -> `v2.15.0` (both `Makefile` pins:
  `golangci-lint:` target and `gopkglist:`), which bundles a new enough
  `x/tools` to read go1.27.2's export data.
- Migrated `.golangci.yml` to the v2 config schema (`version: "2"`,
  `gofmt`/`goimports` moved under a new `formatters:` section, settings
  moved to `linters.settings`/`formatters.settings`, `issues.exclude-dirs`/
  `exclude-files` moved to `linters.exclusions.paths`). No `golangci-lint
  migrate` command exists in v2.15.0 (removed/not yet shipped), so this was
  done by hand against the documented v1->v2 mapping.
- v2 merges the old `staticcheck`/`gosimple`/`stylecheck` linters into one
  `staticcheck` linter covering SA*/S*/ST*/QF* checks. The existing
  `checks: ["all"]` setting, which previously only reached SA* (the other
  three were never separately enabled), suddenly surfaced ~190 new
  S*/ST*/QF* findings — pre-existing style issues, nothing to do with the
  toolchain bump. Restricted to `checks: ["SA*"]` to keep the enforced lint
  surface identical to pre-bump, per the documented migration pattern for
  this exact merge (confirmed via multiple other projects' v2 migration
  PRs hitting the same thing).
- Disabled `errcheck` (41 findings) per repo owner direction — not enforced
  for this repo.

### Alternatives considered

- Go 1.26.9 — smaller jump, same CVE coverage. Went with 1.27.2 instead
  since it was readily available and brings in additional Go 1.27.x
  security fixes (HPACK race, module-checksum bypass) at no extra cost.

## Scope

- **In scope:** Go toolchain version, `golang.org/x/net` floor, the four
  build-container files that track the toolchain version, the remaining
  MEDIUM/LOW pip floors in `docs/sphinx/requirements.{in,txt}`, and the
  golangci-lint v2 bump + config migration needed to keep `api-checks`
  (`make checks`) green under the new toolchain.
- **Out of scope:** the already-dead `golang.org/x/crypto v0.53.0 => v0.55.0`
  replace (MVS now resolves to v0.57.0, independent of this change) and the
  `google.golang.org/grpc` replace — neither is implicated by this CVE set
  and both predate this change.

## Validation

- Unit tests: `make unit-test` — all 14 packages pass under go1.27.2
  (run as root inside `${BUILD_CONTAINER}`; running as a non-root mapped
  user fails unrelated to this change, because `/var/run/exporter` isn't
  writable by a non-root UID — a pre-existing container/test-harness gap,
  not something this change touches).
- Build: `go build ./...` succeeds under go1.27.2 inside the container.
- `go.sum`/`vendor/` were regenerated via `make mod` in the rebuilt
  `${BUILD_CONTAINER}` (not hand-edited).
- Docs: `pip install -r docs/sphinx/requirements.txt` resolves cleanly and
  `sphinx-build -b html docs` succeeds under Python 3.10, with only the
  same pre-existing warnings as before the floor bumps (myst xref/lexing
  warnings unrelated to dependency versions).
- CI parity: `make checks` (`gen vet lint`, the exact `api-checks` job)
  run against a throwaway clean clone of this branch (not the local
  working copy, to rule out local worktree/submodule noise) — passes with
  0 issues.

## Risks and rollback

- Known risks: toolchain bump could in principle surface new vet/build
  diagnostics; none observed in `go build ./...` or `make unit-test`.
- Rollback plan: `git revert` this commit; re-tag `box.rb`/`dev.env` back
  to the prior builder tag if the new builder image needs to be discarded.
