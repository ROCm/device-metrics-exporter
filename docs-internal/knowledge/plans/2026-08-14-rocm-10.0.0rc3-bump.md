# Bump ROCm tarball to 10.0.0rc3

- **Date:** 2026-08-14
- **Author:** Bhanu Kiran Atturu
- **Related PR(s):** (this PR)
- **Related issue(s) / JIRA:** N/A — ROCm prerelease refresh

## Context

The exporter build pins the therock ROCm tarball at `10.0.0rc2`. A new
prerelease `10.0.0rc3` is being cut; the build must point at the new tarball.
At authoring time the rc3 tarball is not yet published (URL returns HTTP 403),
so this bump is prepared ahead of the artifact landing and CI is re-run once the
tarball is live.

## Approach

- Bump `ROCM_VERSION` and `ROCM_TARBALL_URL` in `Makefile` from `10.0.0rc2` to
  `10.0.0rc3`.
- No Dockerfile/entrypoint change: the libamd_smi SO major is derived
  dynamically from the staged file, and rc2→rc3 does not change the SO major
  (stays `.27`).

### Alternatives considered

N/A — mechanical prerelease version bump.

## Scope

- **In scope:** `ROCM_VERSION` + `ROCM_TARBALL_URL` in `Makefile`.
- **Out of scope:** committed amdsmi assets (default path is
  `AMDSMI_FROM_TARBALL=1`, extracted from the tarball at build time), gpuagent
  pin, patches.

## Validation

- **Blocked until artifact lands:** rc3 tarball URL is HTTP 403 at authoring
  time. Cannot build/verify until published.
- **Required before merge:** rc3 tarball returns HTTP 200; `make docker` builds
  clean; `amd-smi version` reports the expected library version; basic
  `amd_gpu_*` / `gpu_*` metrics emit.

## Risks and rollback

- **Known risks:** a new prerelease amdsmi can change SO major (would need the
  dynamic symlink path to pick it up — verify at build) or introduce ABI/metric
  changes. Do not merge without a successful build against the live tarball.
- **Rollback:** revert this PR; `ROCM_VERSION`/`ROCM_TARBALL_URL` return to
  `10.0.0rc2`.
